# QQ 值班提醒机器人设计

## 目标

在 Windows 上提供带中文窗口的 QQ 值班提醒程序。用户可查看、修改并继续安排值班名单；程序每天 20:00 选择第二天的值班人，在群 `1094289617` 发送真正的 QQ @。用户无需修改源码或手填 NapCat 令牌。

## 固定环境与安全边界

- 机器人 QQ：`3851479069`
- 默认群：`1094289617`
- 默认提醒时间：`20:00`
- 默认消息：`@值班人，明天轮到你值班，祝你工作顺利`
- NapCat 配置：`C:\ProgramData\NapCatQQ Desktop\components\NapCatQQ\config\onebot11_3851479069.json`
- 程序只连接现有 NapCat，不启动或关闭 QQ/NapCat，不监听群消息，不提供公网服务。
- 访问令牌仅在运行时从 NapCat 配置读取，永不写入应用配置或日志。

## 文件与数据

- `QQBot.py`：命令行和窗口入口。
- `qqbot/`：排班、持久化、OneBot 客户端、提醒服务和窗口模块。
- `roster.json`：日期、QQ号、姓名组成的对象数组，按日期排序。
- `settings.json`：机器人 QQ、群号、时间和 NapCat 配置路径。
- `sent_reminders.json`：已成功提醒的值班日期。
- `启动值班机器人.bat`：双击启动。
- `tests/`：完全离线的自动测试。

排班数据示例：

```json
[{"date": "2026-09-23", "qq": 3060569778, "name": "郭子旋"}]
```

所有 JSON 使用 UTF-8，写入时先生成同目录临时文件再替换原文件。排班日期不得重复，日期必须为 `YYYY-MM-DD`，QQ 必须是正整数，姓名不得为空。

## 窗口

窗口使用 Tkinter，包含：

- 状态：NapCat、机器人、目标群、自动提醒状态、下一次值班。
- 排班表：显示日期、QQ和姓名，支持添加、修改、删除和保存。
- 继续排班：按用户选择的起始日期新增记录，提供“下一个工作日”按钮跳过周末。
- 发送控制：检查连接、立即提醒明天值班人、确认后强制重发、启动/停止自动提醒。
- 日志：显示时间、操作、发送对象、返回结果和易懂的错误。

网络请求在后台线程执行，结果通过线程安全队列交还 Tkinter 主线程，避免界面卡住。

## 自动轮换与发送

每天本地时间 20:00 计算明天日期并按日期查找排班。无记录时仅写日志。存在记录时先检查已发送记录；已提醒则跳过，除非用户明确强制重发。

发送前依次：

1. 调用 `get_login_info`，确认机器人是 `3851479069`。
2. 调用 `get_group_member_info`，确认目标 QQ 在群内并读取群名片。
3. 调用 `send_group_msg`，提交 `at` 与 `text` 两个 OneBot 消息段。
4. 仅当返回 `retcode = 0` 时登记值班日期。

周末不硬编码为禁发：没有周末排班就不发；用户主动添加周末排班时仍发送。

## 命令行

- `python QQBot.py`：打开窗口。
- `python QQBot.py --dry-run`：显示明天对象，不发送。
- `python QQBot.py --send-now`：立即提醒，遵守重复保护。
- `python QQBot.py --send-now --force`：强制重发。

窗口与命令行必须共用同一套核心逻辑。

## 错误处理与测试

NapCat 未启动、账号不符、群或成员不存在、超时、配置或排班损坏时均不发送、不登记，并指出具体原因。强制重发必须二次确认。

自动测试覆盖日期选择、无排班、重复保护、强制重发、成功后登记、失败不登记、OneBot 消息格式、输入校验、原子保存、NapCat 配置读取、令牌脱敏和工作日计算。自动测试不得连接真实 QQ；真实发送只在用户明确要求时执行。

## 使用流程

用户先启动 NapCat 命令行版并登录，再双击 `启动值班机器人.bat`。窗口保持运行时每天 20:00 自动提醒；关闭窗口会停止提醒，退出前必须提示。当前范围不包含 Windows 开机自启。
